Home Assistant Media Source (openhac4)

Presents a Home Assistant media_player entity in Control4 as a room Listen source through the media_service proxy. Browse the entity's library from Navigator, play items, and see now-playing metadata, progress, transport, and shuffle and repeat, with per-room select and volume.

When to use this driver

Audio plays on the Home Assistant device itself, a streaming-service model rather than Control4 Digital Audio. Use this driver for media players that are a room's own endpoint, such as a Sonos, an AV receiver, or a networked speaker. For programming, status, or players fed through a Control4 audio matrix, use the separate Home Assistant Media Player (openhac4) driver instead. You can add both for the same entity.

Setup

  1. Add the openhac4 Gateway and connect it to Home Assistant.
  2. Add this driver, then pick the media_player entity in the Entity list, or type it into Entity ID.
  3. Bind the driver's audio end-point into the rooms where it should appear as a Listen source.

Features

  • Browse the entity's library through Home Assistant browse_media. Drill into folders and play items.
  • Now Playing: title, artist, album, elapsed progress, and transport for play, pause, stop, previous, and next.
  • Shuffle and Repeat when the entity supports them.
  • Room selection, volume, and mute.

Known limitations

  • Album art is forwarded only when Home Assistant reports an absolute http or https URL. Relative art that needs the Home Assistant address and token is skipped. Re-serving art from controller-local storage is a possible future enhancement.
  • The progress bar advances as Home Assistant pushes new state, not smoothly between pushes.
  • The Now Playing queue shows the current track only. Home Assistant does not expose a full queue across integrations.

Programming

  • Variables: STATE, MEDIA_TITLE, and VOLUME.
  • The driver also creates a read-only HA_<ATTRIBUTE> variable for each attribute the Home Assistant entity reports, named in upper case with non-alphanumeric characters replaced by underscores (an app_name attribute becomes HA_APP_NAME). A small set of metadata and high-churn attributes is skipped (friendly_name, icon, device_class, supported_features, attribution, entity_picture, and media position), and at most 100 are exposed per entity.
