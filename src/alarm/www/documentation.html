Home Assistant Alarm (openhac4)

Maps a Home Assistant alarm_control_panel entity onto a Control4 security panel and a single security partition. Arm and disarm from Control4 call the matching Home Assistant service and pass the entered code straight through to Home Assistant; the panel state, including arming and entry/exit delays, is reflected back from Home Assistant.

Setup

  1. Add this driver to the project. It finds the openhac4 gateway automatically.
  2. Set Entity to the Home Assistant alarm_control_panel entity, or type its id into Entity ID. Use Refresh Entity List if it is not listed yet.
  3. Confirm the driver's Security System connection is bound to the room where the panel should appear. It binds automatically to the room the driver is added to; to surface it in a different room, rebind it under Connections. The Security Panel and Partition connections are internal and need no attention.

Notes

  • The PIN is passed through to Home Assistant, which validates it against the real panel. The Control4 keypad prompts for a code when Home Assistant reports one is required to arm.
  • Home Assistant's arming and pending states are shown as exit delay and entry delay.
  • Zones, local PIN validation, and notifications are not included in this version.
  • Canceling an exit delay from Control4 sends a disarm without a code, so it only works on panels that allow disarming without one. On a panel that requires a code, cancel is rejected and the arm proceeds; disarm normally from the keypad instead.
  • Set Debug to On to reveal the logging controls, then choose a Log Mode and raise Log Level to 4 - Trace to see command traffic. Debug alone produces no output.

Programming

  • Event: State Unavailable, when the entity goes unavailable in Home Assistant.
  • The driver also creates a read-only HA_<ATTRIBUTE> variable for each attribute the Home Assistant entity reports, named in upper case with non-alphanumeric characters replaced by underscores (an app_name attribute becomes HA_APP_NAME). A small set of metadata and high-churn attributes is skipped (friendly_name, icon, device_class, supported_features, attribution, entity_picture, and media position), and at most 100 are exposed per entity.
