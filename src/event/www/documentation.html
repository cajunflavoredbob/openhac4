Home Assistant Event (openhac4)

Surfaces a Home Assistant event entity, a stateless input such as a button or remote press, to Control4 programming. It has no navigator presence; it exists purely to drive programming.

Setup

  1. Add this driver to the project. It finds the openhac4 gateway automatically.
  2. Set Entity to the Home Assistant event entity, or type its id into Entity ID. Use Refresh Entity List if it is not listed yet.
  3. A Control4 programming event is created for each event type the entity reports, for example Single Press, Double Press, or Hold. Detected Event Types shows what was found.

Programming

Under this driver's events you will see one event per detected type. Program against them directly, for example "When Double Press then...". Last Event Type shows the most recent event, and State Unavailable fires if Home Assistant marks the entity unavailable.

  • The driver also creates a read-only HA_<ATTRIBUTE> variable for each attribute the Home Assistant entity reports, named in upper case with non-alphanumeric characters replaced by underscores (an app_name attribute becomes HA_APP_NAME). A small set of metadata and high-churn attributes is skipped (friendly_name, icon, device_class, supported_features, attribution, entity_picture, and media position), and at most 100 are exposed per entity.
  • At most 64 event types are exposed as Control4 events for one entity.

Troubleshooting

  • No events listed: the event types come from the entity's own event_types attribute, so confirm the entity is an event domain entity and that its state has reached the driver. Check Gateway Status and Entity Status first.
  • Set Debug to On to reveal the logging controls if you need a trace of incoming events.
